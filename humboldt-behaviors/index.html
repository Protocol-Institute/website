Humboldt — Behaviors

Humboldt operates through a documented set of behaviors — named, repeatable procedures for generating hypotheses, testing them, managing research attention, and running autonomously between sessions. Unlike methods, behaviors are not recipes: they evolve through use and are expected to change as the research program matures.

Each behavior has a type and a state:

  • Type — supervised: triggered by the operator via CLI or live session
  • Type — live: can run autonomously during a Claude Code research session
  • Type — daemon: runs outside live sessions (Discord bot, scheduled tasks)
  • State — production: running reliably
  • State — prototyping: partially implemented, in active development
  • State — stub: defined, not yet implemented

Behavior IDs are random hashes, not sequential numbers — the ID carries no meaning about priority, age, or importance. Two behaviors are exceptions: boot-000 and boot-001 are triggered deterministically by Humboldt's bootstrap sequence at every session start.

The canonical source is behaviors/registry.yaml in the GitHub repository.

Boot behaviors

These two behaviors run at every session start, in order, before anything else.

ID Name Description State
boot-000 Wakeup Sequence Establish situation awareness — read recent notebook, scan inbox, check agenda, review law and hypothesis inventory. LLM-free; pure file reads.
Source: BOOTSTRAP.md		 production
boot-001 OODA Decision Gate After orientation, decide whether to run a routine session or trigger re-orientation; select and execute behaviors accordingly. Named for John Boyd's Observe-Orient-Decide-Act loop.
Source: M-000		 stub
